## Design Specificity Verdict

**LLM assessment (unanchored):** Genuinely grounded in this product — not a reskin. The tier chips (T0·KING gold-bordered / T1 steel-blue), n/max in-flight against per-backend maxConcurrent, the masthead GPU crease-gauge (skewed 12×9 segments, red top-border on the pending slot when gpu.waiting>0), the prefill row in the readout, and the tape's 429-vs-5xx status split all encode the router's actual semantics (King/Subject admission, bounded queues, prefill caps, explicit 429s) — none of it exists on a generic ops dashboard. The one-hot-color rule is honored end to end (verified across deployed, saturated, folded, hollow states: gold only on live traces, active states, packet control, `est` labels; red only on saturation/offline). Where specificity bends: the hollow/offline state is world-consistent but functionally generic, and the request tape is a feature the product's success metric (latency predictable under contention) doesn't strictly need.

**Deterministic scan:** CLI static scan (detect.mjs) returned 0 findings. The in-page runtime detector (injected via live-server overlay) reported 8 items, all in the masthead/legend cluster: low-contrast all-caps eyebrow ("FLEET SHEET · GPU-AWARE INFERENCE ROUTING"), undersized functional text on the stat strip, the `gpu budget` chip, the est-footnote/PAUSED legend chips, wide letter-spacing on the hollow "sheet offline" line, a `min-height` layout transition, and a zero-offset box-shadow glow (#e4c264, the gold-foil accent). Classification against DESIGN.md: the all-caps eyebrow, the 10px labels, and the letter-spaced micro-copy are the *committed* label treatment (10px / 0.14em / muted) — intentional, not anti-patterns. The `min-height` transition is a one-shot open/close fold, not a loop — borderline, not a perf trap. The gold glow is the spec'd packet-control hover state — false positive. The one detector finding that is a real defect: the muted 10px labels are #6e6a62 on #0a0a0b = **3.68:1 contrast, failing WCAG AA (4.5:1)** — this is the feed row, the est footnote, the tape legend, and the neutral spikes counter; signal red #c0564b is 4.40:1, marginally under AA at its 11px tape/error text.

**Visual overlays:** injected into a dedicated [Human] tab (desktop 1280×900 and mobile 390×844); overlay persisted across resize. Note: the overlay screenshots landed on the mock feed's re-arm gap (hollow "sheet offline — re-arming the feed…" state, all counts 0), so they document the offline state, not full live rows — a timing artifact of the mock, not an asserted defect.

## Overall Impression

The strongest first impression in this project's history: a world with a point of view, executed with real discipline, where the data *is* the decoration and every number is the router's actual in-flight state. The single biggest opportunity is the **failure surface**: this dashboard's job is to tell an operator the truth *at the moment truth stops arriving* — and today that moment is the quietest, emptiest, most generic part of the page. A live, healthy fleet looks extraordinary; a broken feed looks like a placeholder. That is backwards for an operate-in-situ tool.

## What's Working

- **The one-hot-color discipline is actually enforced.** Across deployed/saturated/folded/hollow states, gold appears only as live trace, active states, the packet control, and `est`; red only on saturation/offline. In the saturated state the red inversion (red top crease, red value, faint halo) is the single most legible element on the page — exactly the failure-salience this product needs.
- **The tier/GPU/prefill semantics are drawn, not labeled.** T0·KING gold-bordered chip beside the value, GPU crease-gauge with a red-top next-slot-waiting segment, `prefill 1/1 inflight · 2 wait` in the readout. An operator who knows this router reads the page like a schematic of their own system.
- **The accessible twin ships and is correct.** The `sr-only` flat table has a caption naming it, 10 columns matching the readout, values that track the visible cells live, and the `display:block; width:1px` overflow guard. It is the a11y half of the honest-data boundary, and it is real.

## Priority Issues

**[P0] Dev feed never connects — the shipped dev environment is hollow forever.**
The store hardcodes `/dev-metrics/stream` and `/dev-metrics/burst` (metrics.ts:449, :272), but the mock route is a single SvelteKit `GET` mounted at `/dev-metrics` only — `/dev-metrics/stream` and `/dev-metrics/burst` both 404 (verified with curl: they return the SPA HTML fallback). The feed ladder skips the mock as "gone" and falls to `/stats`, which 502s (vite proxy to a router that isn't up). Out of the box: hollow sheet, gray PAUSED, "re-arming the feed…" forever, and the request tape permanently "the sheet is quiet" even while frames flow, because burst polling 404s silently. Every dev and every reviewer who runs `bun run dev` sees the product at its worst, with a console full of repeating 502/404 noise. Production (router-embedded) is unaffected.
**Fix:** serve both path patterns from the mock route (or split into two +server.ts files), and add a dev-mode console warning when a feed step is skipped as gone.
**Suggested command:** $impeccable harden

**[P0] Feed-loss state has no time anchor and no alarm.**
On drop: hollow "sheet offline — re-arming the feed…" + gray PAUSED chip. No last-data timestamp, no red, no re-try affordance; recovery depends on a 30s stats-fallback watchdog the user cannot see (metrics.ts:487–503). For an on-call operator in a dark room, "the data stopped" must be the loudest thing on the page — today it is the quietest. A 2-second blip and a 20-minute outage are indistinguishable at a glance.
**Fix:** on >6s without frames, freeze the last sheet and overlay a red `STALE — last data HH:MM:SS` banner (red is legitimately available: it is the offline reservation), name the failing endpoint in the feed row, and make PAUSED a different word (DEGRADED/STALE) since PAUSED reads like a user-controlled state.
**Suggested command:** $impeccable clarify

**[P1] Mobile: [DEPLOY] is a dead button and the packet row is a dataless tap.**
At 390px the control reads [DEPLOY] but the sheet is force-folded (narrow ⇒ folded regardless of state — `effectiveDeployed` in +page.svelte); tapping it does nothing visible and `aria-pressed` stays out of sync with the forced state. Packet rows are 45px of truncated name (sglang-subj…), a bare trace, and a value — tapping toggles `is-open` but the folded state hides `.cell-open`, so the tap is a no-op and the row carries no queue/waiting/saturation detail.
**Fix:** either hide the packet control in narrow mode or let narrow follow the button (and keep aria-pressed honest); give the packet row a tap that expands an inline packet readout (inf/wait/prefill) instead of a silent class toggle.
**Suggested command:** $impeccable polish

**[P1] Opened-fold readout is a 14-row wall.**
backend → tok est total, one unbroken 14-row list: lifetime counters (req total, bytes in/out) sit at the same visual weight as live state. For a 15-second glance the operator needs in-flight/queue/prefill/saturation *first*.
**Fix:** lead with a 4-row live-state block; demote lifetime counters to a collapsed totals group — progressive disclosure the system already does well everywhere else.
**Suggested command:** $impeccable distill

**[P2] 60s collapsed trace window makes the cell nearly flat at glance distance.**
The visible line is ~8 samples across ~600px, so a 2→4 in-flight climb reads as a small blip at the right edge. The operator's glance unit is ~15s; the window is 4× that.
**Fix:** default the collapsed window to 30s (keep 60s when opened), or add a window option to the opened-fold switcher.
**Suggested command:** $impeccable optimize

## Persona Red Flags

**Alex (Power User):** No keyboard shortcut for FOLD/DEPLOY — the signature interaction lives behind Tab-Tab-Enter. No compare-two-backends (only one open fold at a time; `open` is a single string). No way to pin which signal a collapsed cell traces (collapsed cells always trace in-flight; changing signal requires opening the fold). Tape speed hardcoded at 34px/s with no control. Reload wipes all open state. Alex gets readout depth but no speed.

**Sam (Screen-Reader / Keyboard):** Solid base — Tab order is sane (packet control → cells in order), focus-visible is a 1px gold-lit outline (verified), Escape works globally and per-cell, aria-expanded/aria-pressed correct, the sr-only flat table exists and is correct. Gaps: (1) after closing an opened fold with Esc/click, focus is lost to `<body>` — a keyboard user is stranded at the top of the document (verified); (2) traces are aria-hidden canvases with no textual trend — the flat table gives numbers but not "rising toward limit"; (3) color-only meaning in the tape: 200-gold / 429-steel / 5xx-red — numbers are present so it's defensible, but st-throttle blue and st-ok gold are easily confused by a color-blind user; (4) contrast: the 10px muted labels (#6e6a62 on #0a0a0b) = 3.68:1, failing AA (feed row, est footnote, tape legend, neutral spikes counter); signal red at 4.40:1 is marginally under AA for its 11px tape/error text.

**Mara (project-specific — on-call ML-infra operator, dark ops room, 3am, 15-second glances):** Three things fail her. (1) Feed drop is the exact moment she needs the page to yell, and it whispers: gray PAUSED + hollow "re-arming" with no last-data timestamp — she cannot tell a 2s blip from a 20-minute outage. (2) Saturation is silent and unanchored: the red inversion has no `since HH:MM:SS` or count-up, so a 2-second 429 blip and a 5-minute saturation look identical, and `spikes n/5s` decays to 0 with no history — the evidence is gone before she notices. (3) The tape scrolls forever with no touch-pause and no 429s-only filter — in a dark room the only way to read a 429 line is to wait for it to drift to center; on mobile there is no pause at all.

## Minor Observations

- [unpatched] `/metrics/stream` and `/stats` proxy to a dead localhost:80, so the console fills with repeating 502/404 resource errors every few seconds — noise a developer will chase.
- The tape field legend sits BELOW the tape; the header row says only `REQUEST TAPE · spikes 0/5s`.
- Masthead status line duplicates the sheet (in-flight in masthead AND every cell) and `tier0 2` has no denominator.
- `PAUSED` as the degraded-feed label is a misnomer — it reads like a user-controlled state; DEGRADED/STALE would fit the red-reservation world.
- Packet rows truncate backend names to ~13 chars (sglang-subj…) at 390px with no tap-to-expand.
- 429 in the tape renders steel-blue (st-throttle), but DESIGN.md reserves red for "429/5xx/saturated/offline" — doc and UI tell two different stories (defensible: capacity rejection ≠ error, but undocumented).
- GPU gauge: 12×9px segments — counting gold segments at arm's length is a chore next to the `2/4 gpu` text that already says the answer; borderline against the gold-is-signal rule.
- The opened-fold fold ✕ button sits inside the signal switcher row at the same size as a signal option.
- `spikes n/5s` has no peak marker or history; it decays and the evidence is gone.
- FOLD/DEPLOY remounts the sheet ({key cascadeKey}), so the trace window resets on every toggle — the scope's virtual clock restarts, losing the 60s of continuity the operator just watched.
- prefers-reduced-motion is well honored (undulation, cascade, sweep, tape scroll, rAF trace scroll all gated — verified in CSS and Trace.svelte).

## Questions to Consider

1. The design system reserves red for 429/offline, yet the shipped tape renders 429 as steel-blue and the degraded-feed state as neutral gray — which failure is the product actually saying is scariest, and does the color system encode that answer, or are the doc and the UI telling two different stories?
2. If the request tape can't reach its endpoint in the shipped dev environment and the traces have no time axis, what is the single number Mara should see first in a 3-second glance — and does the page give it to her (masthead in-flight? GPU gauge? red cell?), or does it make her choose?
3. The signature interaction is "one pull deploys the whole fleet" — but the fleet has two backends. At what fleet size does one global FOLD stop being a feature and start being a nuisance, and does the control survive a 10-backend grid (550ms cascade before the last cell is readable, on top of the trace-window reset it already causes)?
4. The sheet claims operate-in-situ truth, never a stale approximation — but the degraded state shows a hollow plane (zero data) instead of the last true numbers flagged STALE. Is an honest-but-useless empty sheet really more honest than a frozen-but-timestamped one?
